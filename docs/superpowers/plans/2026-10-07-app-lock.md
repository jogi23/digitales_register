# App-Sperre (#114) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die App lässt sich in den Einstellungen per Geräte-Authentifizierung (Biometrie oder Geräte-PIN) sperren: beim Kaltstart und nach einem wählbaren Puffer im Hintergrund.

**Architecture:** Ein Riverpod-Notifier `AppLockController` hält `locked`/`authenticating` und reagiert auf den bestehenden `LifecycleObserver`. Ein `AppLockOverlay` liegt im `Stack` des `MaterialApp.builder` über allem. `DeviceAuth` kapselt `local_auth`; ein MethodChannel `dr/app_lock` verbirgt ab Android 13 die Task-Switcher-Vorschau und schickt die App bei „Zurück“ in den Hintergrund.

**Tech Stack:** Flutter 3.47.2, flutter_riverpod 2.6, `local_auth` ^3.0.2, shared_preferences, Kotlin (`FlutterFragmentActivity`).

**Spec:** `docs/superpowers/specs/2026-10-07-app-lock-design.md`

## Global Constraints

- Nur Geräte-Sperre über `local_auth`, `biometricOnly: false`; keine eigene App-PIN, keine PIN-Speicherung.
- `appLockEnabled` Standard `false`; `appLockGraceMinutes` ∈ `[0, 1, 5, 15]`, Standard `1`, ungültig → `1`.
- Beide Felder app-weit in `settings_global` (in `SettingsState._globalKeys`).
- Kein `FLAG_SECURE`; Vorschau ab API 33 über `setRecentsScreenshotEnabled(false)`, darunter Abdeckung bei `inactive`.
- Sperre nur auf Android und iOS; sonst Schalter verborgen und Controller nie gesperrt.
- Hintergrundabruf, Abmelden und Kontowechsel bleiben unberührt.
- Alle Texte in `app_de.arb` (Vorlage), `app_en.arb`, `app_it.arb`.
- Kommentare im Stil der Umgebung: Englisch, erklärend, wenige.
- Vor Commit: `flutter analyze` ohne neue Befunde, `dart format` auf geänderte Dateien.

## Review Focus

1. **Biometrie-Dialog löst selbst `inactive`/`paused`/`resumed` aus** → darf weder neu sperren noch erneut fragen (Endlosschleife). Test in Task 3.
2. **Geräte-Sperre nach dem Einschalten entfernt** → `notAvailable` entsperrt und schaltet die Sperre ab, statt den Benutzer auszusperren. Test in Task 3.
3. **Kaltstart vor `loadGlobal()`** → erster Frame zeigt schon das Overlay, kein Inhalt blitzt auf. Test in Task 5.
4. **Benachrichtigung/Deep-Link bei gesperrter App** → Route wird darunter geöffnet, Overlay bleibt oben. Test in Task 5.
5. **„Zurück“ bei gesperrter App** → schließt keine Seite darunter, ruft `moveTaskToBack`. Test in Task 5.

### Task 3: `AppLockController`

**Files:**
- Create: `lib/providers/app_lock_provider.dart`
- Test: `test/providers/app_lock_provider_test.dart`

**Interfaces:**
- Consumes: `settingsProvider` (Task 1), `deviceAuthProvider`, `DeviceAuthResult` (Task 2).
- Produces:
  ```dart
  enum AppLockMessage { lockedOut, error, disabled }
  @immutable class AppLockState { final bool locked; final bool authenticating; final AppLockMessage? message; }
  /// Overridden in main() with the value read from settings_global before runApp.
  final appLockInitiallyEnabledProvider = Provider<bool>((ref) => false);
  final appLockClockProvider = Provider<DateTime Function()>((ref) => DateTime.now);
  /// Whether the platform supports the lock (Android/iOS).
  final appLockSupportedProvider = Provider<bool>((ref) => Platform.isAndroid || Platform.isIOS);
  final appLockProvider = NotifierProvider<AppLockController, AppLockState>(AppLockController.new);
  class AppLockController extends Notifier<AppLockState> {
    void onPaused();
    void onResumed();          // may start unlock()
    Future<void> unlock(String reason);
  }
  ```
  `onResumed` braucht den Grund-Text für `unlock`; der Controller hält dafür `String unlockReason` (vom Overlay gesetzt, Task 5) mit Standard `''`.

- [ ] **Step 1: Failing tests** mit `FakeDeviceAuth` (zählt Aufrufe, liefert vorgegebenes Ergebnis) und veränderbarer Uhr, Overrides für `appLockSupportedProvider` (`true`), `appLockInitiallyEnabledProvider`, `appLockClockProvider`, `deviceAuthProvider`:
  - `locked at start when enabled` / `not locked at start when disabled`.
  - `not locked at start when unsupported` (Supported `false`, Enabled `true`).
  - `locks after the grace period`: Sperre an, Puffer 1; `onPaused`, Uhr +59 s, `onResumed` → nicht gesperrt; erneut `onPaused`, +60 s, `onResumed` → gesperrt und `FakeDeviceAuth.calls == 1`.
  - `grace zero locks on pause`: Puffer 0, `onPaused` → `locked == true` sofort.
  - `grace 5 and 15` analog zu 1 (Grenzwerte −1 s / genau).
  - `ignores lifecycle while authenticating` (Review Focus 1): Fake hält `authenticate` per `Completer` offen; während offen `onPaused`, Uhr +20 min, `onResumed` → `calls == 1`; Completer `success` → `locked == false`.
  - `unlock results`: `success` → entsperrt, `message == null`; `cancelled` → gesperrt, kein zweiter Aufruf; `lockedOut` → gesperrt, `message == lockedOut`; `error` → gesperrt, `message == error`.
  - `notAvailable unlocks and switches the lock off` (Review Focus 2): danach `locked == false`, `settingsProvider.appLockEnabled == false`, `message == disabled`.
  - `switching the setting off unlocks`: gesperrt, `setAppLockEnabled(false)` → `locked == false`.
- [ ] **Step 2:** `flutter test test/providers/app_lock_provider_test.dart` → FAIL.
- [ ] **Step 3:** Umsetzen. `build()` liest `appLockInitiallyEnabledProvider` und `appLockSupportedProvider`, hört per `ref.listen(settingsProvider.select((s) => s.appLockEnabled))` auf Abschalten. Sperre gilt als an, wenn `settings.appLockEnabled` oder (vor `loadGlobal`) der Startwert `true` ist; nach dem ersten Settings-Wechsel zählt nur noch `settings.appLockEnabled`.
